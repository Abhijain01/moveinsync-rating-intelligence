# Text for form field 7: "A short note on how you got there and which tools you used"

I treated this as an evidence problem, not a guessing exercise. I confirmed the employee app (com.moveinsync.ets), collected all 24,314 public Play text reviews with google-play-scraper, cleaned and deduplicated them, and analysed the latest 12 months (2,856 reviews; 846 rated 1-3 stars). I built a free, deterministic complaint classifier (26 categories) and tested it on hand-labelled samples (frozen test: precision 0.76, recall 0.65), so counts are approximate. I then wrote a root-cause register with competing explanations and the internal data that would decide each, ranked fixes with a transparent scoring model and sensitivity test, and wrote ticket-level specs a team can start from.

Main findings: app stability (17.7% of low-star reviews) is the largest controllable cluster, with sign-in/OTP next; about 18% of complaints involve transport operations that an app release cannot fix; there is no aggregate deterioration, but install errors rose in July-August 2026. Recommended first step is a one-to-two-week data gate (Android vitals, OTP funnel), then stability and authentication fixes, plus restarting replies to reviews. I do not promise a star target: public data cannot support one, and I explain why. An independent reviewer attacked the first draft; the corrections are listed in the method note.

Tools: Python, pandas, google-play-scraper, pytest, regex rules, all free. Claude (AI assistant) helped with research, code, tests and hand-labelling; the labels were not checked by an independent human, which I state as a limit. The repository includes a reusable tool that answers "How are our ratings?" with one command and 85 automated tests.
